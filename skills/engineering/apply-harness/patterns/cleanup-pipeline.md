# 코드 정리 파이프라인

## 구조: 2단계 (탐지 → 승인 → 정리)

승인 없는 자동 삭제 금지. 탐지 → 사용자 보고 → 승인 후 실행.

## Phase 1: 엔트로피 탐지

entropy 에이전트(또는 메인)가 다음 4가지를 스캔한다:

### 1. 미사용 파일
- import 검색으로 참조 여부 확인
- 생성된 파일이지만 어디서도 import 안 됨

### 2. 문서-코드 불일치
- `CLAUDE.md` 또는 README의 파일 경로가 실제 없음
- 라우트 등록 파일과 실제 뷰 파일 불일치
- API 클라이언트 목록과 실제 파일 불일치

### 3. 중복 패턴
- 거의 동일한 위젯/컴포넌트/함수가 2곳 이상 존재
- 통합 가능한 DTO/모델

### 4. 고착된 TODO/FIXME
- 3개월 이상 된 TODO (git blame으로 확인)
- 이미 해결됐지만 주석이 남은 경우

**산출물:** `_workspace/entropy_report.md`

```
## 엔트로피 리포트

### 자동 처리 가능
- [ ] {파일경로}: {이유}

### 수동 검토 필요
- [ ] {파일경로}: {이유}

### 문서 업데이트 필요
- [ ] {항목}: {현재} → {올바른 내용}
```

## Phase 2: 정리 실행

### 자동 처리 가능 (승인 후 직접 수정)
- `_workspace/` 잔여 파일 삭제
- CLAUDE.md 경로 오류 수정
- 라우트 불일치: 임시 GetPage/라우트 추가 (`// TODO: 뷰 파일 연결 필요`)
- 명백히 데드 코드인 파일 삭제

### 수동 처리 필요 (보고만)
- 정적 분석 에러/경고 — 원인 파악 필요
- 중복 컴포넌트 통합 — 실제 사용처 확인 후 결정
- TODO 처리 방향 — 개발자 판단 필요

## Phase 3: 결과 보고

```
## 정리 완료

**삭제:** N개 파일
**수정:** N개 파일
**보고 항목:** N개 (수동 처리 필요)
```
