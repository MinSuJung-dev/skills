# 오케스트레이션 원칙

## 메인 에이전트 역할

**메인 = 라우터/판단자. 실제 코드 작성 = 전문 에이전트 위임이 기본.**

메인 에이전트는 다음만 한다:
- 요청 유형 분류 → 적절한 스킬/에이전트로 라우팅
- 조사/분석 결과를 자족적인 위임 프롬프트로 패키징
- 산출물 검토 및 사용자 보고

## 에이전트 위임 원칙

위임 프롬프트에는 반드시 포함:
1. **파일:라인** — 수정 대상 정확한 위치
2. **변경 의도** — 왜 이 변경이 필요한지
3. **변경 전후 스니펫** — 가능한 경우 `old_string → new_string` 형식

"근거 없는 위임" 금지 — 조사 결과 없이 "이 버그를 고쳐줘"만 전달하지 않는다.

## _workspace/ 컨벤션

에이전트 간 아티팩트 전달은 `_workspace/` 디렉토리를 사용한다:

```
_workspace/
├── 00_requirements.md    # 사용자 요구사항 (원문 보존)
├── 01_architect_spec.md  # 설계 산출물 (architect → dev 전달)
├── 02_dev_summary.md     # 구현 요약 (dev → qa 전달)
├── 03_qa_report.md       # QA 결과
└── entropy_report.md     # 코드 정리 분석 결과
```

각 에이전트는 이전 단계 파일을 Read하고, 자신의 산출물을 Write한다.

## CLAUDE.md — 프로젝트 지도

모든 프로젝트는 루트에 `CLAUDE.md`를 가진다. 내용:
1. **기술 스택** — 핵심 라이브러리/프레임워크
2. **모듈 구조** — 디렉토리 규칙, 참조 모듈 예시
3. **절대 규칙** — 위반 시 QA NEEDS_FIX 처리
4. **핵심 파일 위치** — 설정, 라우트, API 클라이언트 등
5. **스킬 목록** — 트리거 조건 포함

## 에이전트 팀 vs 서브 에이전트

| 기준 | 에이전트 팀 | 서브 에이전트 |
|------|------------|-------------|
| 에이전트 수 | 2개 이상, 상호 통신 필요 | 1개 또는 결과 전달만 필요 |
| 조율 방식 | SendMessage + TaskCreate/Update | 메인이 순차 호출 |
| 용도 | 교차 검증, 발견 공유, 실시간 피드백 | 경량 변환, 단방향 파이프라인 |

기본값: 서브 에이전트 순차 파이프라인. 교차 검증이 품질에 결정적이면 에이전트 팀.
