# 직접 수정 vs 위임 규칙 (Escape Hatch)

## 직접 수정 조건 (전부 만족 시)

1. 수정 라인 수 ≤ 2줄 (공백·주석 제외)
2. 단일 파일
3. 단순 상수/임계값 조정, 오타 수정, import 추가
4. 사용자가 "X를 Y로 바꿔" 식으로 명확히 지정

→ 메인 에이전트가 Edit 도구로 직접 수정. 에이전트 위임 오버헤드 불필요.

## 반드시 위임해야 하는 경우

다음 중 하나라도 해당하면 dev 에이전트에 위임:

- 3줄 이상 변경 또는 다파일 수정
- 새 함수/클래스/컴포넌트 추가
- 로직 분기 추가/변경 (if/switch/조건문)
- 상태 관리 lifecycle 코드 수정
- 타입/인터페이스/시그니처 변경
- 좌표계/변환 로직 수정

## 위임 프롬프트 품질 규칙

위임 시 메인은 반드시 조사 결과를 포함한다:

**필수 포함:**
- 파일:라인 (정확한 위치)
- 변경 의도 (왜 이 변경이 필요한지)
- old_string → new_string 스니펫 (가능한 경우)

**금지:**
- "이 버그 고쳐줘"만 전달 (조사 없이 증상만 전달)
- 여러 변경을 하나의 모호한 지시로 묶기

## dev 에이전트 수신 규칙

위임받은 경우:
1. prompt에 명시된 변경만 수행
2. 범위 외 리팩토링/포맷 변경/주석 추가 금지
3. prompt가 모호하면 즉시 메인에 되묻기 (자기 판단으로 추가 변경 금지)
4. 완료 후 정적 분석 결과 보고
