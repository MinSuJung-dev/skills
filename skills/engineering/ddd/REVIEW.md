# 설계 검증과 DDD 리뷰

## Phase 6 — 설계 검증 게이트

`docs/domain/reviews/NNN-<scope>-design.md`에 저장한다. 하나라도 `미통과`면 구현하지 않고 사용자에게 보고한다. `해당 없음`은 이유를 적는다.

```markdown
---
scope: <컨텍스트 / 유스케이스>
date: YYYY-MM-DD
result: 통과 | 미통과
---

| 항목 | 결과 | 근거 |
|------|------|------|
| DDD 적용 여부 — 복잡한 규칙이 있는가, CRUD로 충분한가 | | |
| 도메인 경계 — 이 기능이 속한 컨텍스트가 정해졌는가 | | |
| 용어 — 필요한 용어가 모두 glossary.md에 확정됐는가 | | |
| 규칙 — 모든 규칙에 출처(스토리/코드/테스트/사용자)가 있는가, 가정은 표시됐는가 | | |
| 불변식 — 애그리거트마다 지키는 불변식이 적혀 있는가 | | |
| 애그리거트 경계 — 연관관계가 아니라 일관성 경계로 정했는가 | | |
| 엔티티 / 값 객체 구분 | | |
| 로직 위치 — ARCHITECTURE.md 결정 순서를 따랐는가 | | |
| 외부 의존 — 도메인이 포트로만 외부에 닿는가 | | |
| 트랜잭션 경계 — 유스케이스당 애그리거트 하나인가, 아니면 이유가 있는가 | | |
| 이벤트 — 각 이벤트에 반응하는 쪽이 있는가, Domain/Integration 구분 | | |
| 컨텍스트 간 의존 — 방향과 패턴이 context-map.md와 일치하는가 | | |
| 배포 구조 — 모듈형 모놀리스인가, MSA면 ADR 근거가 있는가 | | |
| 브라운필드 — API 계약·마이그레이션·기존 테스트 영향 확인 (해당 시) | | |
```

## 애그리거트 경계 질문 (설계 중·검증 시)

같은 애그리거트에 넣으려는 객체마다:
1. 반드시 **같은 비즈니스 규칙** 안에서 함께 변경되어야 하는가?
2. **같은 트랜잭션**에서 일관성이 즉시 보장되어야 하는가?
3. 외부에서 **독립적으로 변경**될 수 있는가? (그렇다면 분리하고 ID로 참조)

1·2가 아니오거나 3이 예면 분리한다. "관련 있다"는 이유만으로 넣지 않는다.

## Phase 8 — DDD 리뷰

새 서브에이전트나 `codex:rescue`에서 실행한다. 입력: 리뷰 범위(파일/커밋), `docs/domain/`. 이 파일, HEURISTICS.md, ARCHITECTURE.md를 읽는다. **코드는 수정하지 않는다.**

체크 (발견마다 `file:line` + 근거):
1. **용어** — 클래스·메서드·이벤트 이름이 glossary.md 코드명과 다르거나, 용어집에 없는 도메인 개념이 있다. 한 용어가 컨텍스트를 넘어 다른 의미로 쓰인다.
2. **추측된 규칙** — 스토리·테스트·문서에 출처가 없는 비즈니스 조건(기간, 금액, 상태 제한 등).
3. **계층 위반** — 도메인 패키지에서 프레임워크·ORM·HTTP·메시징 import. 엔티티의 저장/전송/알림 호출.
4. **로직 위치** — 애플리케이션 서비스의 비즈니스 `if`, getter/setter뿐인 엔티티, CRUD 모양 서비스(`create/update/delete/find`), 한 줄짜리 도메인 서비스.
5. **애그리거트** — 다른 애그리거트를 객체로 참조, 한 트랜잭션에서 여러 애그리거트 변경, 테이블 구조를 그대로 옮긴 모델.
6. **이벤트** — 구독자 없는 이벤트, 사소한 필드 변경 이벤트, 내부 모델을 그대로 노출하는 Integration Event.
7. **컨텍스트 경계** — 다른 모듈 내부 클래스·테이블 직접 접근, context-map.md에 없는 의존.
8. **테스트** — 확정된 규칙에 대응하는 Domain Rule 테스트가 없다.
9. **과잉 설계** — CRUD 영역에 애그리거트·이벤트·포트 일괄 적용, 근거 없는 MSA·브로커.

## 리뷰 보고 형식

`docs/domain/reviews/NNN-<scope>-review.md`에 저장하고 채팅에는 요약만.

```
DDD Review — <scope>
위반 N (high N / medium N / low N)

HIGH
1. src/order/domain/Order.kt:42 — 계층 위반
   근거: 도메인 엔티티가 PaymentClient 직접 호출
   제안: PaymentPort를 통해 PayOrderUseCase에서 결과 전달

추측된 규칙 (사용자 확인 필요)
- src/order/domain/Order.kt:58 — "결제 후 7일 이내 취소" 출처 없음

"fix 1" 또는 "fix all high"로 승인.
```
